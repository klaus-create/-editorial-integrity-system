# Quality Gate

## Mandatory checks
- [ ] Manifest and input artefact versions are recorded.
- [ ] Objective, reader effect, thesis, message and call to action are distinct.
- [ ] The thesis is authorised or the brief is not executable.
- [ ] Every material claim has an evidence or attribution duty.
- [ ] Permitted inferences and prohibited moves are explicit.
- [ ] Hard constraints and preferences are distinguished.
- [ ] Form architecture defines functional jobs, not decorative headings.
- [ ] Voice instructions are specific to this piece and do not exceed evidence.
- [ ] Impossible length, density or format demands surface a trade-off.
- [ ] Required modules follow risk and consequence; every release condition has a stable ID, owner, action and blocking status.
- [ ] Unresolved conflicts identify an accountable owner.
- [ ] Output validates against the editorial-brief schema.

- [ ] Exact input versions are recorded for every material upstream artefact.
- [ ] No stale input is treated as current, and the output states its own invalidation conditions.

## Failure outcomes
- `conditional`: downstream work may proceed with authorised placeholders or named trade-offs.
- `human_input_required`: thesis, priority or hard-constraint conflict requires a decision.
- `blocked`: the assignment would require unsupported claims, prohibited disclosure or impossible execution.

## Evidence to return
Return the claim-and-evidence matrix, precedence decisions, structure plan, required modules and release conditions.

## Final self-check
Can the brief travel without the original conversation? Did I silently choose a thesis or priority? Does every instruction change a downstream decision?
