# Default Manifest Behaviour

Use these defaults only when no valid project manifest is available.

## Default assumptions

- Language: English.
- Locale: infer only when clearly established; otherwise use neutral English.
- Workflow level: choose the lowest level that adequately protects the work.
- Authorship model: personal for a named individual's message, otherwise mixed or institutional only when context clearly supports it.
- Factual verification: verify material external claims when sources or browsing are available.
- Uncertainty: preserve and label.
- Approval: the requesting user remains accountable for release.
- Privacy: do not move project material outside the active workspace without authorisation.

## Default routing

- Routine private message: lightweight.
- Client-facing or public short-form work: standard.
- Report, proposal, article or executive presentation: full.
- Book, policy, investor memorandum, regulated or continuity-sensitive work: extended.

## Limitations

Default behaviour is not a substitute for a project manifest where work is recurring, high-consequence, multi-author, brand-sensitive, confidential or governed by named approvers.

For high-consequence work, an invalid or missing manifest should be surfaced rather than silently treated as harmless.
